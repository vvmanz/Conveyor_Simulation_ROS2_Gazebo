# conveyor_sim

**Симулятор конвейерной сортировки посылок на ROS 2 и Gazebo Harmonic со сбором RGB-D-данных и управлением заслонками.**

[English](README.md) | Русский

`conveyor_sim` — прототип автоматизированной сортировочной станции. Gazebo моделирует конвейеры и перемещение посылок, а ROS 2 управляет генерацией объектов, получением изображений, передачей классов и исполнительными механизмами. Отдельный узел сохраняет RGB-кадры и карты глубины для дальнейших экспериментов с компьютерным зрением.

## Возможности

- **Сортировочная линия** из SDF-моделей: ленты, наклонные участки, накопители, заслонки и грузы.
- **Автоматическое создание посылок** со случайными моделями, цветами и ориентацией.
- **RGB-D-датасет**: по три RGB-кадра (`.png`) и массива глубины (`.npy`) для каждого отслеживаемого объекта.
- **Три класса сортировки** (0, 1, 2) и управление двумя заслонками по классу и положению посылки.
- **Мост ROS–Gazebo** для команд конвейерам и сообщений камеры.

> **Важно:** сейчас `dataset_recorder.py` после съёмки назначает **случайный класс** для проверки алгоритма сортировки. Это демонстрационный сценарий, а **не обученный классификатор изображений**.

## Требования

- Linux, ROS 2 и Gazebo Harmonic (`gz-sim 8`), совместимые пакеты `ros_gz_sim` и `ros_gz_bridge`.
- ROS 2: `rclpy`, `sensor_msgs`, `std_msgs`, `tf2_ros`, `cv_bridge`.
- Python: `numpy`, `opencv-python` (или системный OpenCV).
- Python-привязки Gazebo Transport: `gz.transport13`, `gz.msgs10`.
- `colcon` и настроенное окружение ROS 2.

Зависимости перечислены по импортам из исходников; отдельного lock-файла в проекте нет. Версии Python-привязок должны совпадать с версией Gazebo.

## Сборка и запуск

Расположите репозиторий в `src/` рабочего пространства ROS 2. Замените `YOUR_REPOSITORY_URL` реальным адресом репозитория, а `jazzy` — установленным дистрибутивом ROS 2:

```bash
mkdir -p ~/conveyor_ws/src
cd ~/conveyor_ws/src
git clone YOUR_REPOSITORY_URL conveyor_sim
cd ~/conveyor_ws
source /opt/ros/jazzy/setup.bash  # замените, если установлена другая версия ROS 2
colcon build --symlink-install --packages-select conveyor_sim
source install/setup.bash
ros2 launch conveyor_sim simulation.launch.py
```

Общий launch-файл запускает мир Gazebo, мост, узел моделирования, запись датасета, сортировщик и статическую трансформацию камеры. Автоматического установщика окружения в архиве нет.

## Архитектура

```text
Gazebo Harmonic                 ROS 2
conveyor_world.sdf              simulation_manager
  ├─ модели конвейеров <------  создание / удаление посылок
  ├─ движение грузов    ------>  координаты объектов
  ├─ RGB-D-камера       ------>  dataset_recorder
  └─ заслонки          <------  sorter_controller
                                   ^
                                   └── /object_classification (JSON String)
```

| Топик | Назначение |
|---|---|
| `/camera/image_raw` | RGB-изображение |
| `/camera/depth_raw` | Карта глубины |
| `/object_classification` | `{"name": "example_000001", "class": 1}` (классы: 0, 1, 2) в `std_msgs/String` |
| `/pusher_1`, `/pusher_2` | Управление заслонками через мост Gazebo |

## Данные экспериментов

`dataset_recorder.py` создаёт `dataset_ozon/` относительно вычисленного пути рабочего пространства. У каждого объекта появляются `rgb/000.png`–`002.png` и `depth/000.npy`–`002.npy`. Перед длительным запуском проверьте фактический каталог выгрузки: он зависит от установки пакета.

## Структура репозитория

```text
conveyor_sim/          узлы ROS 2: управление, съёмка, сортировка, генерация грузов
launch/                общий запуск, Gazebo, мост, узлы
models/cargo/          SDF-модели посылок
models/environment/    модели конвейеров и станции
worlds/                conveyor_world.sdf
package.xml            метаданные пакета ROS 2
setup.py               сборка ament_python и точки входа
```

## Замечания

- Это **инженерный прототип симулятора**, а не готовая промышленная система.
- В исходном архиве есть автоматически созданные `build/`, `install/` и `log/`; при чистом клонировании проект следует собрать заново.
- В `package.xml` зависимость `rclpy` написана как `rlcpy`: исправьте запись, если возникнут проблемы с установкой зависимостей.
